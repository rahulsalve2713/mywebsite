TrolleyMate: Smart Shopping Made Easy

Flutter · IoT · Firebase · Product Design

A smart shopping trolley ecosystem that eliminates checkout queues. Customers scan items directly into a physical trolley, which syncs in real-time to a mobile app and a web-based billing booth.

View on GitHub →

The problem

Retail checkout is slow because the cart doesn't know what's in it. Every item gets scanned manually at the counter — resulting in long queues, human error, and a bottleneck that ruins the shopping experience.

This project asks a simple question: what if you could scan as you shop, and just walk out?

What I built

A complete hardware + software ecosystem that tracks items in real-time, calculates the running bill on the trolley itself, and allows fast, queue-free checkout at a billing booth.

  • Customer Mobile App: Barcode scanning to instantly add items to the cart.
  • Smart Trolley (ESP32): Physical trolley with an LCD showing the live cart total, controlled via UDP.
  • Billing Booth (Web App): A laptop dashboard where cashiers pull up a trolley's cart using a 4-digit code for instant checkout.
  • Admin Dashboard: Full product catalog, category, and user management synced via Firestore.
  • Real-time Sync: Firebase Realtime Database keeps the phone, trolley LCD, and billing booth perfectly in sync.

How it works

  1. Customer logs into the mobile app and enters the 4-digit code printed on their trolley.
  2. As items are added, the customer scans barcodes to add them to the digital cart.
  3. The cart instantly syncs to Firebase, updating the ESP32 LCD on the physical trolley.
  4. At the exit, the cashier enters the 4-digit code into the Web Billing Booth.
  5. The cashier processes the payment, which updates the cart status to "Paid" and clears the session.

What broke

Firebase Web URL Parsing: Flutter Web had a major issue parsing the Realtime Database URL from the `firebase_options.dart` file. It kept throwing `FIREBASE FATAL ERROR: Cannot parse Firebase url`. I had to manually instantiate the database using `FirebaseDatabase.instanceFor()` with the explicit URL on every screen.

Barcode Scanner Whitespace: Scanned barcodes sometimes appended hidden newline characters. When comparing them against the database, they never matched. I had to create a normalization function to aggressively `.trim()` all barcodes on both the admin and customer sides. Also, managing state across three different screens (Admin, Customer, Booth) using local `SharedPreferences` initially caused massive sync issues, forcing a complete migration to Cloud Firestore.

What I'd do differently

If I started over, I would build the hardware-first. I spent a lot of time perfecting the Flutter UI before the ESP32 was even wired up. Once the hardware was ready, I had to rewrite large chunks of the state management to handle UDP connections and LCD latency. I also would have implemented the Weight Sensor (HX711) from day one. Scanning a barcode is easy to fake (scanning a cheap item while putting an expensive one in the bag). Weight verification is essential for a commercial version.
